Function 1 of 4

_apply_env_overrides

src/core/config.py

What it does in one sentence: Scans every environment variable that starts with FINNIE_ and writes its value into the raw YAML dictionary before Pydantic validates it.

Why it exists: In production or CI you cannot edit a YAML file — you inject config via environment variables. This function is the bridge that maps those vars onto the config tree.

def _apply_env_overrides(raw: dict[str, Any]) -> dict[str, Any]:
    """
    Overlay FINNIE_* environment variables onto the raw YAML dict.

    Rules:
      - FINNIE_LLM__MODEL        → raw["llm"]["model"]       (double __ = nesting)
      - FINNIE_LOG_LEVEL         → raw["logging"]["level"]   (special case)
      - Values are always written as strings — Pydantic coerces them later.

    Args:
        raw: The dict produced by yaml.safe_load(config.yaml).

    Returns:
        The same dict, mutated in-place, with env overrides applied.
    """
    for key, value in os.environ.items():
        # ── Skip anything that isn't ours ──────────────────────────────────
        # os.environ contains PATH, PYTHONPATH, OPENAI_API_KEY, everything.
        # The FINNIE_ prefix is our namespace — ignore all other vars.
        if not key.startswith(ENV_PREFIX):
            continue

        # ── Strip prefix, lowercase ────────────────────────────────────────
        # "FINNIE_LLM__MODEL" → "llm__model"
        # Lowercase so it matches YAML keys (which are conventionally lowercase).
        env_key = key[len(ENV_PREFIX):].lower()

        # ── Build the navigation path ──────────────────────────────────────
        # Special case: FINNIE_LOG_LEVEL → ["logging", "level"]
        # Without this, the __ rule would give ["log", "level"] — wrong key.
        if env_key == "log_level":
            path = ["logging", "level"]
        else:
            # Double underscore = one nesting level deeper.
            # "llm__model" → ["llm", "model"]
            # "rag__top_k" → ["rag", "top_k"]
            path = env_key.split("__")

        # ── Navigate to the parent dict ────────────────────────────────────
        # path[:-1] = all parts except the final key (the navigation).
        # path[-1]  = the final key (the destination).
        current = raw
        for part in path[:-1]:
            # Create intermediate dicts if they don't exist in the YAML.
            # Also handles the edge case where YAML has a scalar where we
            # expect a dict — we replace it rather than crashing.
            if part not in current or not isinstance(current[part], dict):
                current[part] = {}
            current = current[part]

        # ── Write the value ────────────────────────────────────────────────
        # Always a string — env vars have no type system.
        # Pydantic will coerce "0.7" → 0.7, "99" → ValidationError, etc.
        current[path[-1]] = value

    return raw

BSkip anything that doesn't begin with FINNIE_. This is the namespace that separates our vars from every other tool's vars.
CStrip the prefix and lowercase: FINNIE_LLM__MODEL → llm__model. Lowercase so it matches YAML keys, which are conventionally lowercase.
DSpecial case: FINNIE_LOG_LEVEL maps to raw["logging"]["level"]. Without this, the double-underscore rule would map it to raw["log"]["level"] — wrong.
EDouble underscore = nesting level. llm__model → ["llm", "model"]. This is the convention: one underscore = part of a word, two = go deeper.

Real example trace FINNIE_LLM__TEMPERATURE=0.7 in environment → key: "FINNIE_LLM__TEMPERATURE" → strip prefix → "llm__temperature" → split on __ → ["llm", "temperature"] → navigate to raw["llm"] → write raw["llm"]["temperature"] = "0.7"
Interview grill
Why does the function return raw instead of modifying it in-place and returning None?

It does both — dicts are passed by reference in Python so the in-place mutation already affects the caller's dict. Returning it lets you write raw = _apply_env_overrides(raw), which makes the data flow explicit at the call site. Neither is "wrong" but the return style documents intent: this function transforms the dict.

What happens if two env vars write to the same key?

The last one wins — it's a simple dict assignment with no conflict detection. In practice this can't happen because env var names are unique within a process. But it's worth knowing: if you somehow had both FINNIE_LLM__MODEL and a custom mechanism writing to the same path, the iteration order of os.environ would decide the winner, which is undefined.

Why isinstance(current[part], dict) check?

Defensive guard. If config.yaml has llm: "some-string" at a key where we expect a nested dict, and then an env var tries to navigate through it, we'd crash with a string subscript error. The check detects that case and replaces the scalar with an empty dict. It's trading "surprising override" for "crash" — usually the right call in a config loader.

Function 2 of 4

load_config

src/core/config.py

What it does in one sentence: Runs the five-step pipeline — dotenv → YAML → env overrides → secrets → Pydantic validation — and returns a fully-typed Config object or raises loudly.

Why it exists: Every module in the app needs config. This function is the single place that touches files, environment, and validation. Everything else just calls get_config().

1load_dotenv(PROJECT_ROOT / ".env") — loads your .env file into os.environ. Does NOT overwrite vars already in the environment. So a container or CI value always beats the file.
2yaml.safe_load(config.yaml) or {} — reads the YAML into a plain Python dict. The or {} handles an empty file (safe_load returns None on empty, which would crash the next step).
3_apply_env_overrides(raw) — overlays FINNIE_* vars onto the dict. Values are still strings here.
4Collect secrets — reads OPENAI_API_KEY from env. If missing or blank → RuntimeError right here, with the variable name in the message. Alpha Vantage is optional.
5Config(**raw) — Pydantic coerces types ("0.7" → 0.7), runs field validators (temperature ≤ 2.0, overlap < chunk_size), and raises ValidationError if anything is wrong.
def load_config(path: Path | None = None) -> Config:
    """
    Load, overlay, and validate application configuration.

    Execution order (each step can override the previous one):
        1. load_dotenv  — reads .env into os.environ
        2. YAML         — reads config.yaml into a plain dict
        3. env override — FINNIE_* vars overwrite YAML values
        4. secrets      — API keys injected from os.environ
        5. validation   — Pydantic coerces types and checks constraints

    Args:
        path: Optional path to a custom config file.
              Used by tests to inject a temporary config.
              Defaults to PROJECT_ROOT/config.yaml.

    Returns:
        A fully-validated, fully-typed Config object.

    Raises:
        FileNotFoundError: config.yaml does not exist.
        RuntimeError:      OPENAI_API_KEY is missing or blank.
        ValidationError:   Any field fails Pydantic's schema rules.
    """

    # ── STEP 1: Load .env into os.environ ─────────────────────────────────
    # load_dotenv does NOT overwrite vars already set in the environment.
    # So a value injected by CI or Docker always beats the .env file.
    # Precedence:  system env  >  .env file  >  config.yaml  >  schema defaults
    load_dotenv(PROJECT_ROOT / ".env")

    # ── STEP 2: Read the YAML config file ─────────────────────────────────
    # Accept a custom path so tests can pass a temp file without touching
    # the real config.yaml.
    config_path = path if path is not None else CONFIG_PATH

    if not config_path.is_file():
        # Fail fast with a message that tells the developer exactly what to do.
        # An opaque FileNotFoundError from deep inside PyYAML is useless.
        raise FileNotFoundError(
            f"Config file not found: {config_path}. "
            "Create config.yaml from the template before starting."
        )

    with config_path.open("r", encoding="utf-8") as fh:
        # yaml.safe_load returns None for an empty file — the `or {}` turns
        # that into an empty dict so the subsequent dict ops don't crash.
        # encoding="utf-8" is explicit: Windows defaults to cp1252, which
        # raises on a rupee sign (₹) or an em dash in a compliance string.
        raw: dict[str, Any] = yaml.safe_load(fh) or {}

    # ── STEP 3: Apply FINNIE_* env var overrides ───────────────────────────
    # Values are still strings here — e.g. raw["llm"]["temperature"] = "0.7"
    # Pydantic coerces them in step 5.
    raw = _apply_env_overrides(raw)

    # ── STEP 4: Collect API secrets ────────────────────────────────────────
    # Secrets NEVER come from YAML — only from the real environment.
    # This keeps them out of version control even if someone commits config.yaml.

    openai_key = os.environ.get("OPENAI_API_KEY", "").strip()
    if not openai_key:
        # .strip() catches a key set to whitespace only (a common copy-paste error).
        # Raise here, not inside Pydantic, so the error names the env var and
        # points at .env.example — not a generic "field required" message.
        raise RuntimeError(
            "Missing required env var OPENAI_API_KEY. "
            "Add it to .env — see .env.example."
        )

    raw["secrets"] = {
        "openai_api_key": openai_key,
        # Alpha Vantage is optional. `or None` converts an empty string to None
        # so the Pydantic field (str | None) gets None, not "".
        "alpha_vantage_api_key": os.environ.get("ALPHA_VANTAGE_API_KEY") or None,
    }

    # ── STEP 5: Validate and return ────────────────────────────────────────
    # Pydantic:
    #   - coerces types: "0.7" → float 0.7
    #   - checks constraints: temperature le=2.0, chunk_overlap < chunk_size
    #   - raises ValidationError with field names if anything is wrong
    #
    # ValidationError is intentionally NOT caught here.
    # A bad config must crash the app at startup, not propagate as a
    # mysterious NoneType error three modules downstream.
    return Config(**raw)

2cencoding="utf-8" is explicit. Windows defaults to cp1252, which crashes on a rupee sign (₹) or an em dash. Always name the encoding when opening text files.

Interview grill
Why does load_config inject secrets in step 4 instead of letting _apply_env_overrides handle them?

Two reasons. The override step writes into nested config keys; secrets live under raw["secrets"] as a whole sub-dict, which is cleaner to inject at once. More importantly, the override step does not validate presence — it just writes if the key exists. Secrets get their own explicit check: if OPENAI_API_KEY is absent or blank, RuntimeError is raised right here, not discovered later as a None comparison error buried in the OpenAI client code.

What does yaml.safe_load(fh) or {} protect against?

An empty YAML file. yaml.safe_load returns None on an empty file, not an empty dict. Without the or {}, the next dict operations would raise TypeError: 'NoneType' object is not subscriptable. It is a one-token defensive guard against a valid edge case.

Why is load_dotenv called before reading YAML, not after?

Because step 3 reads from os.environ. If load_dotenv ran after, the FINNIE_* variables from the .env file would not yet be in the environment when _apply_env_overrides scanned it. Order here is not a style choice — it is load-order correctness.

Function 3 of 4 (pre-written)

get_config

src/core/config.py

What it does: The only config accessor the rest of the codebase should ever call. Wraps load_config() in an lru_cache so YAML is parsed exactly once per process.

@lru_cache(maxsize=1)
def get_config() -> Config:
    """
    The only config accessor the rest of the codebase should ever call.

    @lru_cache makes this a lazily-initialised singleton:
      - First call  → runs load_config(), caches the result
      - Every later call → returns the cached object instantly (no I/O)
      - Tests → call get_config.cache_clear() to force a fresh load

    Why not just call load_config() at module level?
      Module-level code runs at *import* time, which breaks tests,
      docs generators, and causes circular import issues.
      Lazy init via lru_cache is strictly better.
    """
    return load_config()
@lru_cachePython's built-in memoisation decorator. maxsize=1 means it stores exactly one result — the first call's return value. Every call after that returns the same cached object instantly, with no file I/O.

Three things this guarantees:

  • Singleton — every module that calls get_config() gets the same object. No two parts of the app can observe different configs during a run.
  • Lazy — YAML is not read at import time. The first call that actually needs config triggers the load. Cheap imports, predictable startup.
  • Testable — tests call get_config.cache_clear() before each test to force a fresh load with a different temp config. Without this, test isolation would be impossible.
Interview grill
Why not just put load_config() at module level and read it once on import?

Module-level execution runs at import time, which means the .env file must exist and be valid the moment anyone does import src.core.config. That breaks tests that want to override config, breaks docs generation tools that import but never run, and can cause circular import issues if any other module also imports config at module level. Lazy initialisation via lru_cache is strictly better: the work happens on first use, not on import.

Function 4 of 4

setup_logging

src/core/logging_setup.py

What it does in one sentence: Configures the Python root logger exactly once — sets the format, attaches a StreamHandler (always) and an optional FileHandler, then quiets noisy third-party libraries.

Why it exists: Every module in the app needs a logger. This is the one place that sets up the entire logging system. It runs on first use, not at import time.

_CONFIGURED = False   # module-level flag — survives across function calls


def setup_logging(level: str | None = None) -> None:
    """
    Configure the root logger once for the whole process.

    Safe to call multiple times — the _CONFIGURED guard makes every call
    after the first a no-op. This matters in Streamlit, which re-executes
    the entire script on every user interaction; without the guard, each
    interaction adds a duplicate handler and log lines multiply.

    Args:
        level: Optional override (e.g. "DEBUG"). Wins over config.yaml.
    """
    global _CONFIGURED
    if _CONFIGURED:
        return   # ← second call → silent no-op (Streamlit safety)

    # Deferred import — avoids circular dependency.
    # config.py may call get_logger() during its own init; a top-level
    # import here would create a cycle that crashes at startup.
    from src.core.config import get_config
    cfg = get_config()

    # level argument > config.yaml > Python's default WARNING
    effective_level = level or cfg.logging.level
    fmt = logging.Formatter(cfg.logging.format)

    root = logging.getLogger()   # the root logger — parent of all loggers
    root.setLevel(effective_level)

    # ── StreamHandler — always present ────────────────────────────────────
    # Writes to sys.stdout so pytest captures it correctly.
    # (pytest captures stdout, not stderr, by default)
    sh = logging.StreamHandler(sys.stdout)
    sh.setLevel(effective_level)
    sh.setFormatter(fmt)
    root.addHandler(sh)

    # ── FileHandler — optional ─────────────────────────────────────────────
    if cfg.logging.file:
        log_path = cfg.resolve(cfg.logging.file)
        log_path.parent.mkdir(parents=True, exist_ok=True)   # create logs/ dir
        # encoding="utf-8" is mandatory — Windows defaults to cp1252,
        # which raises on a rupee sign (₹) in a compliance disclaimer.
        fh = logging.FileHandler(log_path, encoding="utf-8")
        fh.setLevel(effective_level)
        fh.setFormatter(fmt)
        root.addHandler(fh)

    # ── Quiet noisy libraries ──────────────────────────────────────────────
    # At DEBUG, httpx and openai flood the terminal with HTTP wire logs.
    # Pinning them to WARNING keeps YOUR debug output readable.
    for noisy in ("httpx", "httpcore", "openai", "urllib3",
                  "sentence_transformers", "yfinance"):
        logging.getLogger(noisy).setLevel(logging.WARNING)

    _CONFIGURED = True
globalglobal _CONFIGURED tells Python we want to write to the module-level variable, not create a new local one. Without this, the assignment inside the function would silently create a local _CONFIGURED that disappears when the function returns — the flag would never be set.
root loggerlogging.getLogger() with no argument returns the root logger. All named loggers (like src.agents.portfolio) are children of the root. Setting a handler on root means every child logger in the whole app writes to it automatically — one setup, universal effect.
StreamHandlerWrites log lines to the terminal. sys.stdout instead of sys.stderr because pytest captures stdout — if you used stderr, your log output would be invisible in test output.
FileHandlerOptional — only created if config.yaml sets logging.file. mkdir(parents=True, exist_ok=True) creates the logs/ directory on first run so the app doesn't crash on a missing folder.
The Streamlit bug this prevents: Without the _CONFIGURED guard, every button click re-runs the script → setup_logging() runs again → adds another handler. After 5 clicks: 5 handlers → every log line prints 5 times. The guard is a one-line fix for a subtle production bug.
Interview grill
Why import get_config inside the function instead of at the top of the file?

To prevent a circular import. config.py may call get_logger() during its own initialisation. If logging_setup.py had from src.core.config import get_config at module level, Python would see: import logging_setup → import config → import logging_setup (already importing!) → crash. The deferred import breaks the cycle: Python only resolves it when setup_logging() is actually called, by which time config.py has already finished loading.

What's the difference between setLevel on the root logger vs on each handler?

Two independent filters. The root logger's level is the first gate: if a message is below root's level, it is discarded immediately and never reaches any handler. Each handler then has its own level as a second filter. In practice we set them to the same value here, but you could set root to DEBUG and a FileHandler to WARNING to get everything in the terminal but only warnings in the log file — two different views from one stream of events.

Function 5 of 5

get_logger

src/core/logging_setup.py

What it does: Returns a named logger for a module, ensuring setup has run. Two lines of logic. Called as get_logger(__name__) at the top of every src/ file.

def get_logger(name: str) -> logging.Logger:
    """
    Return a module-named logger, configuring logging on first use.

    Usage in every src/ module:
        from src.core.logging_setup import get_logger
        log = get_logger(__name__)   # ← always use __name__

    Using __name__ names the logger after its module path, e.g.:
        src.agents.portfolio
        src.rag.retriever
        src.workflow.router

    This gives a free hierarchy: you can silence one noisy subsystem
    without touching any of its code:
        logging.getLogger("src.rag").setLevel("WARNING")
    """
    if not _CONFIGURED:
        setup_logging()                    # configure on first use
    return logging.getLogger(name)         # return the named logger
__name__When a module calls get_logger(__name__), __name__ is Python's built-in that equals the module's import path. In src/agents/portfolio.py, __name__ is "src.agents.portfolio". This is the convention — using a hardcoded string like "portfolio" would break the hierarchy.
hierarchyPython loggers form a tree by dot-separated name. src.agents.portfolio is a child of src.agents, which is a child of src. A handler on any ancestor catches all descendant logs. That's how logging.getLogger("src.rag").setLevel("WARNING") silences the entire RAG subsystem in one line.
The rule that never breaks: Every file in src/ has exactly these two lines at the top:
from src.core.logging_setup import get_logger
log = get_logger(__name__)
Then uses log.debug(), log.info(), log.warning(), log.error(). Never print().
Interview grill
Why not just call logging.getLogger(__name__) directly in each module?

Because then setup would never run. The root logger would have no handlers (Python's default), and every log line would hit the "last resort" handler which prints a warning that no handler was found. By routing through get_logger, the first module that asks for a logger triggers setup automatically — no manual call required anywhere, no risk of a module that forgot to call setup.

12 questions — answer them cold
Walk me through what happens when load_config() is called for the first time.

Five steps in order. load_dotenv reads the .env file into os.environ (without overwriting existing vars). yaml.safe_load reads config.yaml into a plain Python dict. _apply_env_overrides scans os.environ for FINNIE_* vars and writes them into the dict — values are still strings. We then read OPENAI_API_KEY from env; if missing, raise RuntimeError right here with the variable name in the message. Finally, Config(**raw) lets Pydantic coerce types, run field validators, and return a fully-typed Config object. ValidationError is intentionally not caught — a bad config must crash the app at startup.

FINNIE_LLM__TEMPERATURE=99 arrives as a string. What happens and where?

_apply_env_overrides writes the string "99" into raw["llm"]["temperature"] — no validation here. When load_config reaches step 5, Pydantic coerces "99" to float 99.0, then checks the le=2.0 constraint — ValidationError is raised inside Config(**raw), naming the field. The app crashes at startup, loudly, before any user sees it.

Why does get_config use lru_cache instead of reading YAML at module level?

Module-level code runs at import time, requiring the .env file to exist and be valid the moment anyone imports config. That breaks tests (which want to inject a custom config), docs generators that import without running, and can cause circular import issues. lru_cache makes it lazy — the work happens on first call, not on import — and testable, since tests call get_config.cache_clear() to force a fresh load.

Why is there a _CONFIGURED flag in logging_setup? What goes wrong without it?

Streamlit re-executes the entire script on every user interaction. Without the guard, setup_logging() adds a new handler on every button click. After n clicks, n handlers are attached to the root logger, and every log line prints n times. The _CONFIGURED flag makes every call after the first a no-op.

Why does setup_logging import get_config inside the function instead of at the top of the file?

To break a circular import. config.py may call get_logger() during its own initialisation. If logging_setup.py imported config at module level, Python would see: import logging_setup → import config → import logging_setup (already importing!) → crash. Deferring the import to inside the function means Python resolves it at call time, by which point config.py has already finished loading.

What is the FINNIE_ env prefix for? Could you just use the raw key name?

The prefix is a namespace. Without it, _apply_env_overrides would scan every environment variable — PATH, JAVA_HOME, USERPROFILE, everything — and try to map them onto the config dict. Any var whose lowercase name happened to match a config key (e.g. PATH → raw["path"]) would corrupt config silently. The prefix guarantees that only variables explicitly set for Finnie are applied.

Your .env file has OPENAI_API_KEY=sk-prod-abc. Someone on CI sets the same var to sk-ci-xyz. Which one wins?

The CI value wins. load_dotenv does not overwrite a variable already present in the environment. The precedence is: system/CI environment > .env file > config.yaml defaults. This is correct behaviour — a container or CI value should always beat a local dev file.

Why does load_config raise RuntimeError for a missing OPENAI_API_KEY rather than letting Pydantic catch it?

Pydantic's error for a missing required field is "field required" with the Python field name — not the env var name, and no pointer to .env.example. A RuntimeError raised explicitly here can name the env var and say "add it to .env — see .env.example". An error message is part of the interface; a good one halves the time it takes a new developer to fix the problem.

Why do we quiet httpx, openai, urllib3 etc. to WARNING level?

At DEBUG, these libraries log every HTTP request and response — headers, payloads, retries, TLS handshakes. That is dozens of lines per LLM call. Your own DEBUG output (router classification, retrieval scores, cache hits) is completely buried. Pinning third-party loggers to WARNING lets you run your app at DEBUG and see only your own output.

What is config.resolve() for? Why not just use the path directly from config.yaml?

config.yaml stores paths as relative strings like "data/cache" because they are relative to the project root. Python functions need absolute paths. resolve() converts a config-relative path to absolute by joining it with PROJECT_ROOT if it is not already absolute. Without it, every consumer would need to know to prepend the project root themselves — repeated knowledge that rots when someone moves the project.

Why call every logger as get_logger(__name__) instead of a custom string?

__name__ equals the module's import path — src.agents.portfolio, src.rag.retriever, etc. This creates a logger hierarchy that mirrors the package structure. You can silence an entire subsystem with one line: logging.getLogger("src.rag").setLevel("WARNING"). A hardcoded string breaks the hierarchy — logging.getLogger("src.rag") would no longer be the parent of a logger named "retriever".

All 14 tests pass. What does that actually prove, and what does it not prove?

It proves the four functions behave correctly for the scenarios the test author anticipated: missing key raises RuntimeError, env overrides apply correctly, duplicate setup_logging calls are no-ops, etc. What it does not prove: that the whole app works end-to-end, that config.yaml is valid for a production deployment, that the logging format is readable to a human, or that edge cases the test author did not think of are handled. Tests are a specification, not a proof of correctness.
