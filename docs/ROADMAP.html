How we work

Development happens in VS Code, in ai_finance_assistant/. Each phase runs in the same four beats:

#BeatWho
1Concept lesson, written into LEARNING_NOTES.htmlMe
2Scaffold: folder layout, class skeletons, type signatures, docstring specs, and acceptance tests that failMe
3Implementation: fill the TODO(you) bodies until the tests passYou
4Code review line by line, then an interview grilling on that phase's conceptsMe → you
Why the tests come before your code. Each phase ships with a tests/ file that fails on NotImplementedError. It is your specification, your definition of done, and — by Phase 12 — most of the 80% coverage requirement, already written. Never edit a test to make it pass.

The stack we are committing to

LayerChoiceWhy this one
OrchestrationLangGraphExplicit StateGraph: nodes, edges, typed state. Orchestration is the single highest-weighted rubric item, and a graph is far easier to defend in an interview than CrewAI's implicit role-play.
LLMGPT-4o, with gpt-4o-mini for routingStrong instruction-following and reliable structured outputs, which the router depends on. Paid per token, so we tier it: the cheap model classifies intent, the big one writes user-facing answers. Hidden behind our own interface so it can be swapped.
Embeddingsall-MiniLM-L6-v2 (local)384-dim, CPU-friendly, zero API cost and no rate limit during indexing.
Vector storeFAISS, flat inner-productIn-process, no server, exact search. 100 articles is far too small for an approximate index to pay off.
Market datayfinance primary, Alpha Vantage fallbackyfinance needs no key; Alpha Vantage gives us a genuine rate-limit problem to engineer around.
UIStreamlitFour tabs, native charts, session_state for conversation memory. Named explicitly in the rubric.
Testspytest + pytest-covA fake LLM and a fake price feed keep tests deterministic and offline.
Compliance is not optional. Every user-facing response carries an educational-use disclaimer, and no agent is ever permitted to say “buy” or “sell”. That is both a stated requirement of the problem statement and part of the 20% Financial Domain Knowledge score.
